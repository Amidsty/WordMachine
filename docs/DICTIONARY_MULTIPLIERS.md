# 词典倍率：实现、协议与升级边界

本批按已提出的推荐方案 A 实施：倍率作用于**每题 Perf 增减**，不是累计 Perf，也不再次乘最终 Rating。代码已接入；之后的全量检查及 [PR #3](https://github.com/WordMachine/Word2Machine/pull/3) 记录见 [发布检查](RELEASE_CHECK_0011.md)。用户当前运行库没有迁移，运行实例前端没有替换，尚未部署。公开版本排除本机专用辅助工具。

## 使用规则

- 每个词典默认 `1.00`，可设 `0.10–5.00`，最多两位小数。新建个人词典时可设置，之后在词典列表/详情的“修改倍率”操作中修改。
- 个人词典由本人或 Lv.5 维护；系统词典（数据库 ownerid 为 NULL）需 **Lv.3–5**。该门槛覆盖倍率、改名、单词增删改、CSV 导入、软删词典，读取/导出范围不变。
- 系统词典改倍率必须填写原因；个人词典原因可选。未增加转移 owner/个人转系统/创建系统词典的入口，不能通过客户端 ownerid 伪造归属。
- 正确和错误的原始 Perf 增减都乘倍率。原有首五场基线、连击、答错重置个人 Perf 的行为保留；不把累计 Perf 或 1500 基线整体乘倍率。倍率 `1.00` 保留原来的数值运算路径。
- 最终 Rating 仍使用原 `legacy-v1` 公式，由实际 Perf 结算，不再乘倍率。人工调分 2B 仍未开放，也不会套用词典倍率。
- Perf/增量只在显示时保留一位小数；数据库和计算保留原始 binary64 数值。
- 可编辑高倍率的简单个人词典仍有刷分空间；没有暗加排位审核或剥夺个人修改权。0 倍不是已实现的练习模式，当前不允许 0。

## 配置接口与审计

`POST /api/dict` 接受 `dictname` 和可选的十进制字符串 `multiplier`（缺省 `"1.00"`）。额外 owner/type 等字段拒绝。

`PUT /api/dict/<id>/multiplier` 示例：

```json
{"multiplier":"1.25","expected_version":0,"reason":"调整词典难度"}
```

要求同源、CSRF、有效账号。服务端升序规则下先锁操作者，再锁词典，重新检查当前等级/归属。倍率、配置版本和 `dictionary_audit` 同事务，审计失败整笔回滚。审计保存词典 ID、操作者 ID/当时等级、前后倍率、版本、原因及实际记录时间，不滥用用户审计表。

倍率和改名均推进 `config_version`。倍率修改必须提交刚审查的版本；冲突返回 `stale_dictionary_version / 409`，不会覆盖。普通改名接口不允许夹带倍率字段。相同倍率不产生无意义的新审计；版本耗尽拒绝写入。

读接口返回规范的十进制字符串、版本和服务端 `can_manage`。数据库使用 DECIMAL(5,2)；输入数字、布尔值、NULL、科学记数法、多于两位小数或越界值拒绝，不偷偷舍入。写请求不自动重发，超时先核对现状；此配置接口采用乐观版本控制，**不是 UUID 回执接口**。

## 创建对局与历史

`game_questions.capture()` 使用同一非锁定 SELECT 捕获词典名称、倍率和题目，保持单一 MVCC 视图，不引入“词典锁 → 用户锁”倒置。

新局 `perf_mode=1`，保存 `multiplier_snapshot`；创建成功后即固定，等待局也不受之后改倍率的影响。原创建 UUID 重放仍返回原局，不重新读取倍率；选择页展示的是预览，最终以创建成功后的服务端快照为准。大厅、房间、详情显示“本局固定倍率”。

已有局为 `perf_mode=0`、倍率快照 NULL，继续旧规则；包括升级时的等待/进行中局。不会用当前词典倍率补造历史，界面显示“旧规则（无倍率快照）”。新规则局缺失/损坏快照或原始增量则拒绝读取/评分，不回退到旧规则。

新规则答案保存 `raw_perf_delta`（乘倍率之前）及实际 `perf_delta`。旧答案新列保持 NULL，旧 JSON 不增加猜测字段。现有答案字段 `rating_version` 沿用名称，但此处标识答题 Perf 规则：新局为 `dict-perf-v1`，旧局为 `legacy-v1`。对局 DTO 新增 `perf_rule_version` 与 `multiplier_snapshot`。

**Perf 规则和最终 Rating 规则已区分**：`game_settlement.rating_version` 和 `rating_event.rule_version` 仍为 `legacy-v1`，因为最终 Rating 公式未改。答案、最终结算、事件链、余额和命令回执仍同事务，不维护另一条评分写路径。历史及转换工具不会重新判题、掷随机数或转换旧规则。
