# 名字颜色修复

本文保留颜色修复批次的实现及 805 项 Python 验证记录。其运行源码随后按授权经 [PR #2](https://github.com/WordMachine/Word2Machine/pull/2) 交付并由维护者合并；最新 811 项回归与新增故障范围见 [N2 认证故障验证](AUTH_FAILURE_TESTS.md)，本轮未再改颜色组件或评分。

## 原因与实现

原 Vue 姓名只有普通文本/链接，没有 Rating 颜色绑定；普通链接统一继承主题蓝色。大厅/对局的用户摘要还缺少当前公开 Rating，无法可靠着色。可见本地代码与旧源码没有保留下来的颜色阈值，因此本次**采用 Codeforces 常见分档作为显示规则**，不声称恢复了已核实的历史阈值；需要调整时只修改共享组件与主题样式，不改评分。

- [`UserName.vue`](../frontend/src/shared/ui/UserName.vue) 统一按 Rating 选固定 class，颜色集中在 [`theme.css`](../frontend/src/shared/styles/theme.css)。已接入导航、排行榜、公开/本人资料、用户管理及弹窗、大厅房主/成员、对局房主/轮次/作答与评分/答题记录。
- [`auth.public_person()`](../wm_app/services/auth.py) 只输出 `{id, username, rating}`；大厅复用原有当前页成员批量查询，对局复用既有成员/房主查询，不新增 SQL 次数或浏览器逐用户请求。缺失用户仍保留原引用/缺失展示。
- 对局/大厅摘要的 `rating` 是读取快照时的当前公开余额，**不是 Perf、本局结算后 Rating 或其他历史记录**。公共摘要中 `deleted != 0`（含 NULL）时该字段为 NULL；原历史评分读取不改，不把缺失值补成 0。管理员用户管理仍使用其已有授权接口的数据。
- `gamePersonSchema` 保留该字段，兼容旧响应省略 Rating；未提供、NULL 或无效值用中性色。颜色没有权限含义，不允许用户提交样式或修改评分。用户名仍通过 Vue 文本插值转义，不使用 `v-html`；3000+ 首字黑色由 CSS 完成，不拆分/改写 Unicode 字符串。
- 名字颜色随所绑定数据刷新而更新；不承诺未刷新页面会实时收到其他对局的全站 Rating 变化。原身份隔离、版本/回执、草稿和命令重试策略保持不变。

| 当前 Rating | 名字显示 |
|---|---|
| 未提供 / NULL | 主题中性色，不当作 0 |
| <1200（含合法负分和 0） | 灰 |
| 1200–1399 | 绿 |
| 1400–1599 | 青 |
| 1600–1899 | 蓝 |
| 1900–2099 | 紫 |
| 2100–2399 | 橙 |
| 2400–2999 | 红 |
| ≥3000 | 红，首字黑 |

## 验证

- 新增 **13 个 Python 单元、1 个真实 MySQL** 用例，验证公开投影、0/负分/NULL、封禁/未知状态不额外公开余额、大厅/对局摘要一致且读取不改原始行；原历史用例另验证后续结算改变当前颜色字段，但不改变本局保存的结果/评分。
- 新增 **25 个 Vitest** 用例，覆盖全部分档边界、缺失/非有限值、响应式更新、Unicode/HTML 转义及当前 Rating 与历史结算/Perf 分离。
- 新增 **1 个模拟 API 浏览器检查**，使用实际构建产物验证全部色阶的 computed CSS、链接 hover、导航与资料页、3000+ 首字、转义及不逐用户请求。既有真实 MySQL 浏览器场景补上大厅、对局、导航、管理列表及弹窗的实际颜色断言，不伪造成功业务响应。
- 完整 `make check-with-mysql`：**805 Python（559 单元 + 246 MySQL）、181 Vitest（16 文件）**，100 个 Python 文件静态检查、前端 lint/格式/类型/构建通过；**14 个模拟 API 浏览器检查、5 个真实 Chromium 场景 + 4 个独立编排/SQL 核对**通过。另运行当前 34 场景 smoke/1 基准通过，非生产性能验收。

当前 head/readiness 仍是 `0008_list_indexes`；没有迁移、依赖升级、评分规则/写协议变更或业务库操作。前后端应同步部署，重新构建前端并重启旧后端进程，才能为大厅/对局提供新字段；颜色修复批次结束时仅本地构建，随后按授权交付源码；没有生产发布。CI、多浏览器及生产验收仍未执行。
