# 用户、管理员与词典真实浏览器验收

此前的管理浏览器批次补齐第 2 阶段的本地核心全流程及维护权限矩阵。使用实际 Vue 构建、Flask/Socket.IO 和隔离 MySQL，**不模拟成功业务 API、不用 SQLite、不连接业务库**。该管理验收批次没有修改应用业务规则、写协议、评分、依赖版本或数据库结构；当时 head 为 `0007_game_settlements`，当前发行版就绪要求见 [迁移指南](AUTH_MIGRATION.md)。

后续新增的自然会话到期与 429/Retry-After 场景见 [N2 认证故障验证](AUTH_FAILURE_TESTS.md)；该文记录当前 7 个真实浏览器场景/6 个独立编排的完整回归。本文件保留原管理批次的限定范围与历史数字。

## 组织与证据

- `tests/browser/conftest.py` 从原对局编排提取共用 `run_browser(spec)`：每个 pytest 用例取得独立的合成旧库，显式迁移后启动随机回环线程化服务器。各 spec 单独启动 Playwright；不会因管理测试改密或删词典影响对局测试。
- `frontend/mysql-e2e/support.ts` 复用 UI 登录及独立 Cookie 上下文的创建/关闭。越权探针在 Chromium 内执行同源 `fetch`，携带真实 Cookie 和 CSRF，只绕过隐藏按钮，不绕过后端权限。
- `tests/browser/test_management_browser.py` 在浏览器结束后独立查询 MySQL。该组还对比旧用户的 Rating/历史/最新指针及旧对局 JSON/版本/来源，确保用户和词典操作没有重算或转换历史。
- 测试夹具会明确将合成旧局 `id=1` 设为 **CANCELLED=2**，避免大厅自动进入运行局；这只是隔离夹具安排，不是生产修复或转换策略。撤销测试使用该局的真实只读 Socket 订阅，不需新增对局。
- 注册、词典创建的请求有意加入伪造身份/归属字段；一次词典创建有意改成无效 CSRF。拦截器只转发给真实服务器，不伪造响应。既有对局场景只在真实传输上制造断线/确认丢失。

## 三条新增场景

### 1. 注册、资料、密码与会话

`frontend/mysql-e2e/auth.spec.ts`：

- 旧 `uid/pwhash` Cookie 不能登录且被删除；注册密码确认失败不发请求。
- UI 注册只能创建普通用户，忽略请求中的 root、UID 和 Rating；大小写别名重复注册由真实 MySQL 唯一约束拒绝。
- 新密码保留首尾空白；去掉空白的密码不能登录。会话公开响应不含密码哈希/会话摘要，Cookie 为 HttpOnly、SameSite=Lax，不能经 `document.cookie` 读取。
- 登录轮换 CSRF；匿名旧 CSRF、缺失 CSRF 的写入被拒绝，伪造 UID/角色不能修改其他人。
- 仅改简介不需密码、不撤销另一会话；当前密码错误时简介和密码都不改，当前会话仍可用。
- 改密后全部旧会话撤销：实际 Socket 在关闭轮询时仍退出；另一浏览器的旧表单不能提交；复制旧 Cookie 也不能访问受保护 API。
- 旧密码及去空白新密码失败，正确新密码可重新登录；简介按文本显示并支持深链接刷新。
- 登出只撤销当前会话，另一独立会话仍有效；重放已登出 Cookie 失败，最后再显式登出另一会话。

SQL 核对只有一个新增账户、角色/余额正确、简介完整、scrypt 精确验证新密码、旧密码失效及无残留会话。

### 2. 管理员重置、封禁与恢复

`frontend/mysql-e2e/admin.spec.ts`：

- 匿名不能读取用户列表；普通用户即使伪造 root/UID/旧凭据，也不能读取列表或执行三种管理操作。
- 普通用户直达 `/admin/users/` 返回真实 HTML 403，管理导航不显示该链接；管理员不能通过管理 API 重置、封禁或恢复自己，自己的行不显示操作按钮。
- UI 搜索目标、确认密码校验、实际重置密码；两个目标会话均撤销，旧表单写入被拒，关闭轮询的实际 Socket 退出，复制旧 Cookie 失败。
- 旧密码失败，新密码可登录；封禁后再次撤销两个会话，默认列表隐藏目标，正确密码也不能登录，公开资料 HTML/API 均返回 404。
- 勾选包含封禁用户后可恢复；恢复后公开资料重新可读，但重置前、封禁前的全部旧 Cookie 仍被拒绝，必须新登录。

SQL 核对目标恢复正常、只有目标密码被重置、失败旧表单未改简介、最终所有测试会话已登出；既有评分/历史不变。

### 3. 词典、单词、CSV 与权限

`frontend/mysql-e2e/dictionaries.spec.ts`：

| 身份/归属 | 验证范围 |
|---|---|
| 匿名 | 列表、详情、单词列表、导出及创建拒绝 |
| 普通用户 / 系统词典 | UI 只读；重命名、删除、增改删单词和 CSV 导入六种直接写请求均拒绝 |
| 普通用户 / 他人词典 | UI 只读、可读和导出；上述六种写请求即使伪造角色/归属仍拒绝 |
| 创建者 / 自己词典 | 创建、重命名、单词增改删、文件/文本导入、完整导出、搜索/跨页、删除词典 |
| 管理员 | 维护他人词典名称/单词；系统词典重命名、单词新增/删除、CSV 导入和整词典删除 |

另外验证：

- 无效 CSRF 返回真实 403，客户端刷新会话但不自动重复创建；人工再确认才创建，归属始终取当前会话，SQL 中没有失败/伪造/重复创建的词典。
- 重命名不清 CSV 草稿；恶意单词按文本显示，不能生成图片/执行脚本。
- 非 UTF-8、超过 512 KiB 的文件在前端拒绝且不发送导入；后端收到第二行错误的 CSV 后整批不写，前端保留草稿及物理行错误。
- 含 BOM、引号、逗号和多行字段的文件真实导入 22 条；连同原单词共 23 条，实际翻页/搜索可用。创建者在筛选后及只读用户下载的 CSV 都逐字核对完整内容，不只导出当前页或搜索结果。
- 删除单词后不能修改复活；删除词典后同步软删除全部单词，旧只读详情刷新清除导出入口，管理员也不能读取、导出或向已删除词典新增单词。

SQL 独立核对两个词典的归属/名称/软删除，以及全部 28 条单词的原文、允许的修改和软删除；不存在失败 CSV 的首行或越权插入。

## 运行、结果与边界

```bash
make check-with-mysql
make test-browser
make test-browser-mysql

# 仅运行新增管理场景；需已有前端构建和浏览器
.venv/bin/python scripts/with_test_mysql.py -- \
  .venv/bin/python -m pytest tests/browser/test_management_browser.py -q -s -p no:cacheprovider
```

管理浏览器交付时的完整回归：**622 项常规 Python（433 单元 + 189 MySQL）、156 项 Vitest、13 项模拟 API 浏览器检查**通过，lint/格式/类型/构建通过。独立真实浏览器套件现有 **5 项 Chromium 场景（2 对局 + 3 管理）和 4 项 Python 编排/SQL 核对**，全部连续三轮通过。编排用例不混入 622 项常规 Python；不是新增 9 条独立业务场景。`npm audit` 无已报告漏洞，Python 依赖兼容检查通过。

每个 spec 仍有 210 秒父进程超时；单场景 90 秒、动作 15 秒、断言 10 秒，无自动重试。失败 trace 分别保存在 `frontend/test-results/mysql/<spec 名>/`，不会被后续 spec 清掉。可处理 SIGTERM、失败和超时仍回收所属进程/临时库；管理浏览器批次曾重测实际运行期间的 SIGTERM，返回 143 且无所属进程/临时 MySQL 残留。SIGKILL/断电不保证清理。trace 含合成凭据和 Cookie，只作受控测试产物，不应用这套夹具连接真实账户或业务库。安装、专用 CI 入口及清理限制见 [测试环境](TEST_ENVIRONMENT.md)。

**验收限定为本地 Chromium、单进程回环服务器与合成 MySQL 的上述流程。** 没有验收所有浏览器、网络/会话故障组合、生产规模性能、HTTPS Secure Cookie/可信代理、多 worker、授权旧数据副本或恢复演练。真实浏览器限流/自然会话到期与更多并发故障仍可继续补充；已有相关后端集成测试不冒充浏览器证据。CI 已有统一入口但尚无执行结果。后续 [Python 检查批次](PYTHON_CHECKS.md) 已接入全项目格式/静态 lint，最新计数见 [测试环境](TEST_ENVIRONMENT.md)；历史转换和上线仍按 [PLAN.md](../PLAN.md) 独立推进。
