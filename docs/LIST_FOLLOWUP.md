## 候选实验：保留回到原方案的复测

候选均只存在于隔离实验脚本，没有进入应用。每个分布依次运行原方案、两个候选、再次原方案；每个场景一次预热、五次采样，保留不利结果。顺序复测可以揭示部分波动，**不是随机交错实验或因果证明**。

### 计数结果携带边界，分页不再聚合

六种 medium 分布，各测 9 个搜索场景：热点 contains/literal/miss/common/chinese/contains_last，小词典 contains/literal/miss。

1. **匹配边界**：COUNT 同时计算匹配行的 MIN/MAX，页查询绑定这两个真实端点；COUNT 保留原作用域 JOIN。
2. **作用域边界**：COUNT 同时用 ANY_VALUE 取唯一边界行的端点，页查询复用端点；该字段在同一边界行中固定，不是从历史或估算值猜测。

所有所测结果摘要相同，但没有稳定改善，且新增聚合/SQL 形式有成本：

- standard 的高命中 `words.common`：原方案 22.55、匹配边界 24.60、作用域边界 22.02、再次原方案 22.97 ms。
- deleted 的 `words.literal` 首轮：8.53 / 23.68 / 9.09 / 8.69 ms；**独立复跑**则为 8.87 / 7.58 / 8.40 / 8.09 ms。首次不利样本不删除，但也不把未稳定复现的约三倍差异断言为 SQL 的固有代价。估算页计划两者仍选词典范围索引，不能捏造为“转主键扫描导致”。
- sparse 的 `words.contains_last` 首轮：4.34 / 7.00 / 4.25 / 4.37 ms；复跑为 4.24 / 3.99 / 4.97 / 4.66 ms。
- 小词典、未命中和高命中搜索没有一致收益；候选所测 9 场景的摘要一致不等于已完成全部语义/并发验收。

因此暂不采用，不增加 ANY_VALUE 维护负担，也不凭某次匹配范围更窄就宣称更快。

### 用户 `(deleted, id ASC/DESC)` 临时索引

六种 medium 分布，各测 10 个用户/榜单场景；两种索引仅在准备阶段 ADD/ANALYZE，随后 DROP，最后回到原结构复测。索引形状、可见性、空间估算和计划均保留；只在合成库操作，不构成新迁移方案。

- deleted 用户首页首轮：原结构 3.22、ASC 3.23、DESC 3.61、原结构复测 3.33 ms；独立复跑为 3.01 / 3.20 / 3.12 / 4.86 ms。
- 首轮两个新索引均可见并在候选 key 中，但首页仍选择原评分索引并 filesort，没有稳定解决回表/排序。
- wide 首页首轮看似从 7.95 降至 5.02/5.25 ms，但删掉候选后原结构为 4.71 ms；独立复跑为 5.35 / 5.32 / 5.44 / 4.55 ms。不能忽略准备操作、缓存和宿主波动，把全部差异归功于新索引。
- 各变体所测结果摘要一致；由于尚无稳定读收益，没有继续包装为正式迁移或声称完成新增索引的全写入/恢复验收。
