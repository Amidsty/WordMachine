# 对局题目快照与旧数据边界

此前已完成**新创建对局**的题目快照；不恢复或转换旧对局，不改 `legacy-v1` 评分。已有请求幂等、状态版本及 HTTP/Socket 共用命令服务保持不变。

## 何时固定题目

- 首次创建成功时，而非开局或第一次答题时，固定题序、英文答案、中文题面和词典名称。等待期间、进行中及结束后均使用同一份内容。
- `services/game_questions.py` 在创建事务内用**一条 InnoDB 一致性 SELECT**读取未删除词典及全部未删除单词，再随机排序、写入快照。不会分别读取名称和单词而混入不同时间的数据。
- 应用数据库连接显式使用 `REPEATABLE READ`，不继承服务器可能设置的 `READ UNCOMMITTED`。单条捕获语句即使在 `READ COMMITTED` 下也有一致视图；不锁源词典/单词，不引入“词典 → 用户”的新锁顺序。
- 快照代表捕获语句看到的已提交版本，并非提交瞬间的词典版本。捕获后并发修改/删除词典，可以与创建同时成功；已捕获内容不再变化。不会包含另一个未提交事务的部分改动。
- 对局行、全部快照行、版本基线 0 和成功请求回执**同事务提交**；任何一步失败全部回滚。同 ID 重放成功创建返回原对局，不重新取词、排序或捕获；重放迁移前的创建回执也不会把旧对局转换成快照。
- 保留原字符串，包括大小写、首尾空白、斜杠备选答案、Unicode 和 CSV 换行，不在捕获时修正内容。NULL 词典名称保留 NULL；空/缺失/非法单词文本拒绝创建，返回 `invalid_dictionary_data / 409`，不跳过坏单词。
- 过渡期仍受 `game.wordlist` 的 TEXT 容量约束。序列化 ID 清单超过 65535 字节时返回 `dictionary_too_large / 400`，不截断题目或让数据库静默截断。

## 存储与读取

显式迁移 `0004_game_questions`：

- `game.question_mode`：非空整数，默认 0，CHECK 只允许 0/1。0 为旧的动态词典引用；新创建显式写入 1。
- `game.dictname_snapshot`：可空 UTF-8 名称，不把旧名称填入此列。
- `game_question`：`(game_id, position)` 联合主键，题序从 0 开始；`(game_id, word_id)` 唯一，题序非负、来源 ID 为正的 CHECK，英文/中文非空，UTF-8 文本。
- `game_id` 有 RESTRICT 外键；`word_id` 仅用于来源追踪及兼容现有答题协议，**没有到源单词的外键**。源词典/单词删除不使快照失效。

保留旧 `wordlist` 作为题序/数量的过渡完整性清单，读取快照时核对完整连续题序、来源 ID、数量和文本。题目内容只来自 `game_question`，不把两个来源混用；后续规范化迁移再移除冗余清单。新局参赛关系已由 [参赛关系表](GAME_PARTICIPANTS.md) 接管，旧参赛 JSON 需显式转换；新局已接入 [答题关系表](GAME_ANSWERS.md)；未来结算已接入 [评分流水](GAME_SETTLEMENTS.md)，历史评分及未转换的旧答案仍存原 JSON。已有快照与参赛父关系、答题字段完整的旧答案可使用 [受限转换工具](ANSWER_CONVERSION.md)；该工具不创建快照，也不把 `legacy_live` 改成历史原题。

“不可变”指应用仅在创建事务插入快照，后续只读；词典编辑、删除、CSV 导入及管理员接口都不能修改它。**不是数据库管理员防篡改承诺**：没有阻止特权 SQL 改写的触发器，也不能检测所有看似合法的手工改动。生产运行账号应只获快照表 SELECT/INSERT 权限，另设迁移账号，并保护备份。

快照缺行、题序/清单不一致或文本异常时，状态读取及新写命令返回 `invalid_game_snapshot / 409`；绝不回退到现有词典、补空文本或自动修复。已提交的原成功回执仍可重放，不代表当前快照已经恢复正常。普通业务操作不推进或重写题目快照。

## 对外展示

- `GET /api/game/<id>` 和 Socket `game.update` 新增 `question_source: "snapshot" | "legacy_live"`。[Vue 播放页](GAME_PLAYING_UI.md) 和 [历史详情](GAME_HISTORY_UI.md) 显示相应来源说明；未知来源不冒充快照，Vue 读取边界拒绝未知标记。
- `words`、`next_word`、判题及成功回执的 `expected` 使用同一个题目读取入口。未作答题目只返回 ID/中文，已完成位置才公开英文；提前结束也不公开未答英文。
- 大厅摘要和搜索，以及对局详情的词典名，统一使用快照名称；NULL 不回退到后来改过的源名称。旧对局仍显示/搜索现有名称。
- 词典 CRUD 不改已有快照，也不推进本局 `version`。版本排序对局命令及显式参赛/答案转换，不能当整个响应的 ETag；用户资料和其他对局评分依然可能变化。
- 登录用户仍可查共享词典，快照与隐藏答案不是完整防作弊措施。

## 旧对局：明确未恢复

迁移只增加结构和默认标记：所有已有行的旧 JSON、Rating、评分历史、版本和请求回执保持原值；`question_mode=0`、`dictname_snapshot=NULL`，不填任何历史快照行。

旧对局仍使用 `legacy_live` 来源，同样走共享状态机、权限、判题及评分流程。词典后来改过时，当前文本**不能证明是当时原题**。不能把今天的词典复制为“恢复的历史快照”；后续需在授权副本上审计，确定来源证据、转换策略和不可恢复记录的展示方式。旧题引用丢失时返回 `legacy_data_error`，不悄悄缩短题目列表。

`audit-legacy` 兼容迁移前后结构，新增单词文本、快照题序/完整性、未知模式及孤立快照检查。有效快照不依赖源词典/单词继续存在；旧引用仍检查原表。报告只含问题类型和实体 ID，不输出题面、英文或名称。零问题不代表旧对局已有历史快照。

## 发布与验证

- 本文对应 `0004_game_questions`；当前发行版的 head/readiness 以 [迁移指南](AUTH_MIGRATION.md) 为准。快照迁移在 DDL 前检查同名部分结构、主键类型及 game/dict/word 的 InnoDB 引擎；不自动执行迁移，不对业务库写入。
- MySQL DDL 可能部分提交；停止旧写入、备份并在授权副本演练后再升级，见 [迁移指南](AUTH_MIGRATION.md)。旧应用会继续用动态词典判题，不能与新应用混写。
- 不支持删除快照的 downgrade。不能用清空快照表、把模式改回 0 或只回退应用来“恢复”；需匹配的备份、应用及开放写入后的数据保留方案。
- 真实 MySQL 回归覆盖词典增删改及物理源删除后继续 HTTP/Socket 答题和结算、未答题隐藏、NULL 名称、精确文本、并发创建/答题/结束、捕获与词典写入交错、未提交数据隔离、失败回滚、唯一键/CHECK/FK、损坏检测、只读审计、迁移预检及保留旧值。
- 这些是隔离实例与合成数据测试；不代替授权旧数据副本、备份恢复、生产规模性能或双用户浏览器验收。
