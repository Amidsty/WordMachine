# Vue 播放页与统一 Socket 客户端

本批接管 `/game/<id>/`，保留 URL、Flask 登录守卫和业务 API/事件。所有业务页面均已迁移 Vue；删除最后的 Jinja 页面、旧导航/认证适配器、独立脚本和 CSS，不再使用 CDN Socket 脚本。该播放页交付批次没有数据库迁移、历史转换、评分公式或后端写接口变更；当时 head 为 `0007_game_settlements`，当前发行版就绪要求见 [迁移指南](AUTH_MIGRATION.md)。

## 页面与职责

- `GamePlayingPage.vue` 组合读取、连接、命令和弹窗；`GameTurn.vue` 只显示当前题目/轮次和收集答案。等待状态提供大厅入口，报名/退出/开始/取消仍由大厅完成；观众只读。
- 复用 `GameOverview`、`GameScores`、`AnswerHistory`，不复制评分计算或重新判题。题目来源、历史缺失字段、精度及本局 Rating 定位沿用 [详情规则](GAME_HISTORY_UI.md)。播放页答题表最新在前，详情仍按原顺序；翻页保持真实题序/题目对应。仍是客户端分页，接口返回完整本局记录/用户评分历史，生产规模成本未验收。
- 轮次仅使用服务端 `next_turn/next_word`，不在浏览器计算轮次顺序；结束按钮的成员提示也不授予权限。后端仍验证身份、成员、状态、版本和题目。
- 全部文本经 Vue 转义，无内联事件或 HTML 拼接。轮次/题目实际推进才清空输入；同版本姓名更新或只有存储转换的版本变化不清空草稿。页面卸载/账号、角色或 CSRF 会话身份改变时重建页面，不持久保存草稿或意图。
- 大厅、播放与详情之间使用 Vue Router；登录白名单支持规范 `/game/<id>/` 和 `/game/<id>/detail/`。Vite 仅代理 API、Socket 和健康检查，不再代理旧页面/静态目录。Flask 仍是显式路由，无全站 fallback；缺构建返回 503。

## 传输与会话

`shared/api/socket.ts` 使用锁定的 `socket.io-client 4.8.1`，从 npm 构建打包。每个播放页面有私有连接/Manager（`forceNew`），不跨页保留房间。连接到浏览器当前源，不能传任意外部 URL；同源 Cookie、Origin 校验不放宽。

- 每次连接/重连通过公共会话客户端重新读取会话，并在握手发送 CSRF。每条事件也发送当前 CSRF，服务端逐事件重新验证身份。HTTP 与 Socket 共用客户端会话失效/CSRF 错误策略；旧会话的迟到错误不能清掉新账号/会话。
- `useGameFeed` 负责本局订阅、状态协议/目标 ID 校验和连接状态。每次成功订阅再 GET 修补订阅窗口；重连仅重新认证、订阅和读取，不恢复写请求队列。
- **只读订阅不是写命令。** 握手或传输升级尚忙时，`game.subscribe` 可以正常排队；否则 volatile 订阅可能被丢弃。答题/结束始终使用 `timeout(...).volatile.emit`，`retries=0`，即使从检查连接到发送之间发生断线，也不缓存写操作等待重连。
- 实时连接尚未订阅、不可用或用户关闭“启用实时连接”时，新的手动操作选择 HTTP。传输一经选择，不因超时、断线或错误自动换传输再发一次。
- 只认与当前发送关联的 acknowledgement，再检查其中的请求 ID/版本；不消费重复 `game.answer_result` 或没有请求关联信息的 `game.error` 来完成当前命令。服务端保留这些事件供其他消费者使用。
- 离页撤销请求等待，移除监听，关闭私有连接/重连器。连接断开立即触发只读核对；已失效会话由 HTTP 或有归属的 Socket 错误进入登录页。后端加入订阅/报名房间时，只忽略“读取/提交后连接已关闭”的竞态，不吞掉连接仍有效时的房间错误。

## 状态不来自回执

`useGameState` 是播放/详情共用的权威状态入口：GET 与已校验的 `game.update` 共用版本、题序、终态防回退。忽略其他局推送；未知来源/未来英文等非法响应不用于显示。

- 一个页面只保留一个在途 GET。推送先更新之后，先前 GET 的失败、较旧或同版本返回不能擦掉较新的推送；同版本的新读取仍可更新名字/旧词典文本，版本不是完整 ETag。
- 命令后若有提交前开始的 GET，先等其结束，再发一次新的 GET。命令回执从不填充状态、累加 Perf、清除其他意图或直接跳转。
- 只有已接受的完整状态为 FINISHED，且本地没有未确认命令/结束确认弹窗，才导航到详情。回执确认丢失但状态已推进时，保留原意图供手动核对/重试，不假定哪个操作造成了推进。
- 读取失败清除旧展示但保留版本水位。GET 和命令等待均有 10 秒上限；中止等待不撤销服务器事务。读取失败由读取资源显示，不把已确认写入改称失败。
- `usePolling` 每 5 秒只读核对，后台/离线/手动关闭、命令待确认或结束弹窗期间暂停；离页清理。关闭轮询不会关闭 Socket，关闭 Socket 也不关闭轮询，两项控制明确分开。

## 请求意图与人工恢复

`commands.ts` 定义意图，`useGameCommand` 负责唯一在途意图、超时/取消和通知。答案、题目、对局、操作者、预期版本和 UUID 在首次确认时冻结；提前结束在打开确认弹窗时固定审查版本。

1. 收到有效成功回执后显示“回执已确认”，再读当前状态；评分只取完整状态。读取失败不等于写入失败。
2. 失败、断线或超时后保留原意图，禁止直接发另一新答案/结束命令。**不会自动重发。** 用户可先刷新核对，再点击“重试原请求”，仍用原 ID/参数/版本，即使期间状态推进或传输从 Socket 换为 HTTP。
3. “放弃回执并重新操作”只清理本地意图，明确不代表撤销或回滚；先核对状态，再发起新意图/新 ID。旧版本的失败命令不被擅自换成新版本重试。
4. 离页/刷新/身份变化会丢失内存中的意图，不承诺恢复未确认写入。重新进入后应先核对状态；不能把网络错误解释为服务器没写入。

幂等、锁、评分、权限和事务仍只在后端实现，详见 [命令协议](GAME_COMMANDS.md)。

## 验证与边界

- 前端单元/组件测试覆盖传输选择、握手忙时的只读订阅、请求 ID 绑定、丢弃写包/超时、迟到回执、跨传输人工重试、版本/进度防回退、同账号更换会话、取消、确认弹窗、观众、等待/取消、终态导航及刷新失败。
- 13 项既有模拟业务 API 浏览器回归继续保留；大厅到播放页改为实际 Vue 路由，不再使用旧页面落地桩。它们仍不验证数据库业务。
- `make test-browser-mysql` 的对局部分在新的私有 MySQL 实例运行 **2 项真实 Chromium 场景**：两个独立 Cookie 上下文登录、真实词典创建/CSV 导入、大厅创建/报名/开局、Socket/HTTP 答题、真实 WebSocket 关闭后重连、自动结算/详情刷新；另模拟已提交 HTTP 响应丢失，手动原 ID 重试并提前结束、检查未答英文隐藏和登出撤销。
- 浏览器场景不模拟成功 API 响应或评分；WebSocket 代理只转发实际后端数据/制造断线，丢失确认通过真实 `route.fetch()` 提交后中断客户端响应实现。Python 编排器另查询真实 MySQL 的答案、版本、请求、结算/评分行和用户最新余额，验证没有因重试增加记录。
- 两条对局场景顺序运行于同一个合成测试库，由 `tests/browser/test_game_browser.py` 的一个 Python 用例统一核对最终数据库。共用编排已提取至 `tests/browser/conftest.py`；新增的 [3 条管理场景](MANAGEMENT_BROWSER_TESTS.md) 各自使用独立测试库，不会改密/删词典干扰本组。编排器复用迁移夹具，以 127.0.0.1 随机端口启动线程化 Werkzeug；Node 子进程不接收数据库配置。超时/失败/可处理 SIGTERM 会回收自己的浏览器进程组、服务器和数据库；SIGKILL/断电不保证清理。
- 这证明本地 Chromium、单进程 Flask/Socket.IO、MySQL 的上述对局流程；用户/管理员/词典核心维护权限矩阵由独立管理场景验证。两者都不是受信反向代理/TLS、多 worker、所有浏览器/网络故障、生产负载或历史数据恢复验收。Werkzeug 只是测试服务器，不是生产部署方案。

完整命令、隔离限制和当前计数见 [测试环境](TEST_ENVIRONMENT.md)。未连接业务库、未转换真实旧数据。
