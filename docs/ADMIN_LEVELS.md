# 管理员等级：第一批交付与升级边界

第一批为代码和定向测试交付，不代表已有实例完成升级。没有更改用户正在使用的数据库、现有 admin 的名称/密码，没有在该库创建 MASTER。第二批 Rating 流水基础见 [统一流水阶段说明](RATING_EVENTS.md)；当前应用已要求 0012，本文 0009 命令仅是等级升级步骤。第一批未开放调分接口；后续 [人工调分 2B](MANUAL_RATING.md) 已加入本地代码，需另行迁移才生效。

## 已实现的规则

- `user.admin_level`（整数 0–5）是权限权威；`type` 仅兼容投影，数据库约束两者一致。注册固定 0，不能通过请求伪造等级。
- 管理员只能编辑、重置密码、封禁/恢复严格下级；可以编辑自己用户名/简介，但不能自行提降级、自封禁或恢复。本人改密仍需当前密码。
- 等级调整时，目标当前等级及拟授等级都必须小于操作者等级；被封禁用户先恢复并重新审查。`expected_version` 防止复用过期审查，需填写原因。不自动重试，不以超时推断回滚。
- 管理写入升序锁定操作者/目标，再核验最新状态与等级。变更、审计和目标会话撤销同事务；提交后断开本进程目标 Socket。审计失败整笔回滚。
- 个人词典仍由本人维护，只有 5 级能跨所有者维护。第一批当时保留任意管理员可维护系统词典；后续 [词典倍率批次](DICTIONARY_MULTIPLIERS.md) 已明确收紧为 **Lv.3 起维护系统词典**，不是 Lv.5。登录可读/导出的范围不变。
- Rating 门槛为 4，与双方 Rating 大小无关，可面向本人或严格下级；第一批的 `can_adjust_rating` 始终为 false，资料接口仍拒绝 Rating 写入。
- 会话返回等级，管理列表返回能力及审查版本；前端按等级更新身份页 key，并使用后端能力控制按钮。服务端不会信任按钮或前端校验。

## MASTER

全新本地实例的显式初始化创建 `MASTER`、等级 5、24 位安全随机密码，包含大小写字母、数字、符号。凭据仍仅写入实例的私有 `initial-login.txt`，可用 `./start.sh --show-login` 查看，不写入源码、公开日志或仓库。

已有专用库显式执行 `python -m flask --app app create-master`，隐藏输入并确认密码，要求 16–128 字符及四类字符。`create-admin NAME --level 1` 仅创建 1–4 级账号；普通注册保留 MASTER 名称。发现数据库排序规则认为同名的账户即报冲突，绝不覆盖密码、改名或自动提权。权限来自等级而非名称。MASTER 的用户名固定；5 级账号本人改密也检查复杂度。

旧管理员的密码哈希、名称不会由迁移重置；无法从旧哈希证明密码复杂度。分配旧管理员等级必须人工审查，建议明确选 1–4 级，再单独创建 MASTER，不能宣称迁移自动强化了旧密码。

## 0009 显式升级（不是执行授权）

1. 停止所有旧应用写入；备份并在授权副本验证恢复与升级。禁止新旧应用混写。普通启动不执行升级，也不会重置/改名已有 admin。
2. 使用单独的迁移账号配置目标专用库，核对当前版本及所有 `type='root'` 的账号 ID（包括封禁账号）。审核每个账号拟分配的 1–5 级。未知旧角色必须先人工审查，不能默认按普通账号处理。
3. 对 **已审核副本** 显式执行，例如只有旧管理员 ID 17、获批分配 2 级时：
   ```bash
   python -m alembic -x 'admin_levels={"17":2}' upgrade 0009_admin_levels
   ```
   示例 ID/等级不可照抄。映射必须精确覆盖全部旧 root，拒绝遗漏、多余 ID、重复 JSON 键、布尔等级及非规范 ID。空库没有旧管理员时不需映射。已有 root 却只执行 `upgrade head` 会在首次 DDL 前拒绝。
4. 迁移新增等级、行政版本、约束和 `admin_audit`，设置新普通账号的兼容 type 默认值，记录经审核的旧管理员映射并撤销这些管理员的会话；不改 Rating、历史 JSON、密码或用户名。
5. 显式创建 MASTER，核验登录/等级及下级管理、个人词典权限，再同步构建前后端并启动匹配版本。不能以仅页面能打开代替 readiness 与权限核验。

MySQL DDL 隐式提交：失败可能留下部分结构。检测到等级列或审计表已存在时拒绝盲目重试；不能改写 0001–0008、`stamp head` 或自动接管部分 DDL。0009 禁止自动 downgrade：恢复经过验证的备份及匹配应用，不能删除权限列后让旧 root 恢复广泛权限。

本地 `start.sh` 的持久库使用独立配置，**不读取业务 .env**；以上手工命令不自动连接那个库。已有本地实例升级仍需单独授权、停写/备份和明确旧管理员 ID 映射，不要再次 `--init-local` 或删除数据目录来绕过升级。
