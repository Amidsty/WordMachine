# 旧答题记录：显式单局转换

`convert-game-answers` 只把**可逐项保留的既有答题记录**从 `game.result` 转入 `game_answer`。默认只读；不创建历史题目、不重新判题/抽取随机分数、不转换或重算历史结算。只有隔离 MySQL 合成数据验证，**尚未转换真实旧数据**。

## 适用范围与拒绝边界

答案工具基于 `0007_game_settlements` 的数据结构；使用当前发行版时仍须按 [迁移指南](AUTH_MIGRATION.md) 部署匹配的 head/readiness 与应用。工具本身不执行 DDL，交付该工具时没有新增结构迁移；后续列表索引不改变转换协议。

1. 必须已经有模式 1 的完整题目快照；数量、连续题序、来源 ID 清单和文本有效。不读取当前词典。`legacy_live` 即使零答案也拒绝，错误码 `answer_conversion_requires_snapshot`；不能先把今天的单词复制成历史快照来绕过检查。
2. 必须已有模式 1 的参赛关系，顺序/人数/房主/用户引用完整；保留软删除用户的历史引用。尚未转换时为 `answer_conversion_requires_participants`，应另按 [成员转换流程](GAME_PARTICIPANTS.md#默认只读的单局转换) 审查并转换，再重新读取版本。工具不会自动转换成员。
3. 旧结果必须是明确的 JSON 数组；`[]` 可以代表空历史。NULL、空字符串、非法 JSON、重复对象键、非标准 NaN/Infinity 均拒绝，不能把含糊缺失当作零答案。
4. 每条须完整包含且仅包含：`uid/word_id/answer/result/usercombo/globalcombo/perf_delta/perf/rating_version`。不填默认值、推测规则版本、从相邻 Perf 反算增量或丢弃额外字段；即使保留了原始存档，也不能悄悄丢掉原有字段的读取语义。
5. 沿用答题存储边界校验轮次、连续前缀、成员/题目对应、状态、布尔正确性、非负整数连击和 `legacy-v1` 标记。答案必须已是原规范化形式，不自动去空白或改大小写；Unicode 扩展文本保留。等待/取消不能有答案，进行中不能已经答完整局却没有结束。
6. Perf 和增量保存原 Python JSON 解码后的有限 binary64 数值；整数须能被 DOUBLE 精确表示，否则拒绝。拒绝负零，不依赖 SQL/文本协议消除其符号。允许精确整数在返回协议中表示为等值浮点数；JSON 原始字节、数字词法写法留在存档，不声称恢复已经缺失的原始精度。
7. 不覆盖或合并已有部分答题关系。存在新结算时，按共享结算边界校验状态、结算头、人数、评分行和最后 Perf；旧模式意外出现新结算也拒绝。**不审定旧 `perf/ratingdelta` 存档、用户游戏/评分历史或全库余额链。**

来源无法逐项复制时返回 `unconvertible_game_answers`；目标前缀或现存关系损坏为 `invalid_game_answers`，父关系/快照及结算异常沿用各自错误码。报告只含对局 ID、数量、版本或通用错误信息，不输出提交内容、题面、用户名和评分。

`ready` 只表示该只读快照中的答题数据符合本工具转换条件，不表示全局审计、评分数学或历史来源证据已通过审查；也不保证数据库写权限、网络或下一次版本仍有效。反过来，`audit-legacy` 零异常也不意味着所有旧格式都能无损转入当前表。不能为满足工具而修改原记录、补造字段或改模式。

## 操作流程

先按 [迁移指南](AUTH_MIGRATION.md) 确认目标库、停止旧写入，完成授权、备份、恢复和副本演练。建议维护窗口；工具每次仅处理一局，没有隐含全库批量或 HTTP/Socket 入口。

```bash
# 默认只读事务，无任何转换写入。
.venv/bin/python -m flask --app app convert-game-answers --game-id 123
# 示例：{"game_id":123,"status":"ready","answers":12,"version":7}

# 只有授权审查完成后才执行；7 必须替换成实际审查版本。
.venv/bin/python -m flask --app app convert-game-answers \
  --game-id 123 --apply --expected-version 7
# 示例：{"game_id":123,"status":"converted","answers":12,"version":8}
```

- `--apply` 必须指定版本；在对局 `FOR UPDATE` 锁内重新校验来源和版本，而非盲信先前报告。过期为 `stale_game_version`；版本耗尽拒绝，不写入部分数据。
- 先锁对局，再按用户 ID 升序取得用户引用共享锁，最后插入答题行；不升级为评分排他锁，不锁其他对局。与正常评分的固定锁顺序兼容。
- 保持原题序、作答者、答案、实际正确性、连击、评分和规则标记。**不再执行判题或评分公式**；结构校验不是对所有合法形状历史错误/特权 SQL 篡改的证明。
- 历史 `answered_at=NULL`，`recorded_at` 为本次转换 UTC 微秒写入时间，不冒充作答或事务提交时刻。空数组只切换来源/数量，不插入答案或结算。
- 全部行、`answer_mode=1`、数量和版本加一原子提交；写后回读验证内容/时间未被 SQL 改变。正常异常整批回滚。原 `result` 字节、题目/成员、对局状态、评分/结算、用户历史/余额/最新指针及成功回执不改写。
- 已规范化则校验实际关系并返回 `already_normalized`，不读取存档或再次更新时间/版本；指定的预期版本仍须匹配。
- 业务错误退出 1 并输出 JSON；非法 CLI 参数由 Click 拒绝。数据库错误输出 `conversion_database_error`，不泄露连接/SQL内容。**连接在提交确认时丢失不等于未提交**：先以默认只读命令核对状态、版本和数量，必要时进一步审查，不自动重放或承诺回滚。

## 转换后的兼容与恢复

关系成为唯一来源，原 JSON 是不再更新的存档；后续答题仅追加新行，新答案有实际写入时间，旧行及未知历史时间不变。旧成功命令仍重放原回执/原版本，不重新记分；新命令须使用新读取的版本。转换本身不广播，现有读取/轮询恢复状态。

**禁止仅把模式改回 0、清空答题表或回退旧应用。** 存档不包含转换后的新答题；这样会丢失已接受结果、破坏轮次与结算。使用匹配的已验证备份及应用版本，并单独处理开放写入后的新增数据。应用启动、普通读取和结构迁移均不会调用转换器。

单元与真实 MySQL 回归覆盖严格源校验、未知时间、精度/Unicode、旧迁移升级后的显式转换、原值/余额/回执保留、已结束旧局不补流水、未来追加与 HTTP/Socket 重放、并发转换/最终答案/结束、跨局锁顺序、只读快照、失败回滚、回读差异和提交确认丢失。它们不能代替授权副本转换、旧题恢复、备份恢复、生产规模性能或真实数据库双用户浏览器验收。
