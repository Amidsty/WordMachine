# 本地一条命令启动

此入口用于**当前 Linux 主机上的独立、持久化开发实例**，不是生产部署，也不接管原有数据库。不要 sudo。

## 本机日常使用

**版本提醒：人工调分代码新增 `0012_manual_rating`；本批未操作持久实例，此前本机库为 0011。需要另行授权备份及保留数据升级后再启动新版，否则 readiness 会返回 503。不要用 `--init-local` 或删库解决版本差。**

```bash
cd /home/sunsnow/WordMachine
./start.sh
```

终端显示服务已启动后打开 **http://127.0.0.1:5000/**。每次启动先重新构建 Vue 的 CSS/JS，再只读检查数据库版本；构建失败或版本不匹配就停止，不用旧页面冒充成功。

全新初始化的管理员为 `MASTER`（5 级），使用 24 位复杂安全随机密码。普通启动不会对已有实例自动改名、重置或升级。此本机实例已另经明确授权，在完整冷备份及副本恢复验证后清空重建为 0011，当前仅有全新 MASTER；旧数据仅在私有离线备份中。其他需要保留数据的已有库先按 [管理员等级升级说明](ADMIN_LEVELS.md) 审核并显式迁移。在另一个终端查看：

```bash
./start.sh --show-login
```

可以在运行时查看；这只是读取初始凭据文件，**不重置密码**。首次登录后可在“修改资料”中改密，改密后初始文件里的旧密码失效。不要把输出、凭据文件或数据目录发到公开仓库。新注册用户仍为普通用户、Rating 为 0；没有为了演示颜色伪造评分或历史。

- 停止：原终端 **Ctrl+C**，应用和它启动的 MySQL 会退出，**已提交的数据保留**。确认丢失的写请求仍需核对状态，停止不等于回滚。
- 再次运行 `./start.sh` 即使用同一份本地数据和稳定密钥；不会再次建表、迁移、创建账号或重置密码。
- 端口占用时：`./start.sh --port 5001`，然后打开 `http://127.0.0.1:5001/`。不会关闭占用端口的其他程序。
- 不必激活虚拟环境、不必手工启动 MySQL，也不必设置 `.env`。
- 同一实例不允许同时启动两次；生命周期文件锁随进程释放，不靠旧 PID 文件杀进程。
- 若项目在远程主机，应使用 SSH 端口转发后在本机打开页面，例如 `ssh -L 5000:127.0.0.1:5000 用户@主机`。不要为了方便把这个开发服务器直接暴露到公网。

## 数据与配置在哪里

默认位于 `~/.local/share/wordmachine-local/<项目路径摘要>/`；当前工作区对应 `317ffa433eca`。终端会打印实际目录；可用 `XDG_DATA_HOME` 选择另一处**绝对路径**。路径必须足够短，以满足 Unix socket 长度限制。

- `data/`：这个独立 MySQL 的持久数据。
- `settings.json`：初始化完成标记、匹配的项目路径、MySQL 二进制位置、随机数据库密码和稳定应用密钥。
- `initial-login.txt`：初始管理员凭据，改密后不自动更新；可自行删除它，不影响数据库或正常启动。
- `mysql.log`、`launcher-error-*.log`：本地诊断日志，可能含敏感诊断信息，不公开上传。

实例目录必须是本人所有的 `0700`，配置/凭据文件是 `0600`；拒绝符号链接、宽松权限和不匹配的配置。不要删除整个目录来“修复启动”。移动项目目录、修改 `XDG_DATA_HOME` 会选择不同实例，不自动搬运或接管旧数据。初始化不完整时保留文件并拒绝盲目重试，不自动删库重建。

这是开发数据的持久化，不是已验证的备份恢复方案。不要直接拷贝运行中的 MySQL 数据目录当备份，也不要把它作为唯一的业务数据存储。

## 首次准备或修复依赖

**本机已按下面流程准备。普通启动不需要重复安装。** 其他 Linux 主机先安装受支持的 Python、Node 和兼容 MySQL 二进制/资源，不能把本机成功当作跨系统安装保证。

```bash
# 必须先停止运行中的本地应用，再安装/修复依赖。
./setup.sh

# 仅首次创建全新独立本地实例时执行：
./setup.sh --init-local
```

`setup.sh` 创建缺失的 `.venv`（有 uv 时选 Python 3.11，否则要求已有 Python 3.10+），安装项目固定版本依赖，执行 `npm ci` 和前端构建。完整工作区安装 `requirements-dev.txt`，精简树若无该文件则安装 `requirements.txt`。不升级清单/锁文件，不覆盖已有虚拟环境，不安装系统服务。这里固定的是项目清单及 npm 锁，不声称 Python 所有传递依赖均已有完整锁定。

`--init-local` 才会初始化新数据目录、建立独立数据库、显式运行迁移到当前 head，并通过认证服务创建 `MASTER`（5 级）；已有数据、配置或初始化痕迹一律拒绝覆盖。**只运行 `setup.sh` 不会创建/迁移数据库。** 重复 `--init-local` 会拒绝数据库初始化，但前面的依赖安装/前端构建仍会执行，所以不要对正在运行的实例这样做。

本机已提供：

- `.venv`：Python 3.11.17，运行/开发依赖安装兼容。
- `~/.local/share/wordmachine-tools/node/`：独立的 Node 22.23.2 / npm 10.9.8 用户目录副本；启动脚本显式加入 PATH，不依赖编码工具注入的环境。
- `~/.local/share/wordmachine-test/mysql/usr/`：MySQL 8.0.42 的二进制及资源，供不同实例复用；**不复用测试或业务 datadir**。安装与版本边界见 [测试环境指南](TEST_ENVIRONMENT.md)。其他主机可在显式初始化时传 `./start.sh --init --mysql-basedir /绝对路径/mysql/usr`，该目录只能提供二进制/资源。
- `frontend/node_modules/`：按原 `package-lock.json` 重装；Chromium 仅用于测试，普通启动不需要启动浏览器测试进程。

这个脚本不自动安装系统 MySQL/Node，不修改系统 Python、不用 sudo；当前主机的基础依赖已另行配置。缺少二进制或不支持的系统应先按测试环境文档准备，不会偷偷连接系统 MySQL。

## 隔离与安全边界

- 明确忽略 `.env` 和继承的 `WM_*` 业务连接配置。若要使用自己已有的开发库，请按 [README 手工开发环境](../README.md#手工开发环境已有专用数据库) 操作，**不是改这个启动器去接管数据**。
- MySQL 使用 `--no-defaults`、独立 datadir、仅 `127.0.0.1` 随机 TCP 端口和私有 Unix socket；初始化的临时空 root 密码阶段禁用 TCP，随后立刻设置随机密码。
- 只有显式初始化通过本实例的私有 socket 使用迁移权限。正常应用账号只获本库 SELECT/INSERT/UPDATE/DELETE，无 DDL 权限。
- 普通启动使用 `--upgrade=NONE`，不自动升级 MySQL 系统结构；应用只读 readiness 检查也不会执行迁移。新代码有新迁移或二进制需升级时必须另行制定备份/升级步骤，不能靠重启跳过。
- 本地实例使用单独且稳定的 Cookie 名，避免与其他当前版本 localhost 应用的默认 Cookie 名混用；不改变原应用默认 Cookie 协议。
- 使用单进程线程式 Werkzeug 开发服务器及原应用工厂；HTTP/Socket 权限、CSRF、事务、幂等和评分服务不另写一套。关闭额外的原始访问日志，保留应用现有不含查询参数/Cookie 的请求日志。
- 不开 debug、不扩展 CORS，不提供自动写重试或自动重连数据库进程；仅回收本次创建的子进程组。SIGKILL、断电或系统崩溃不保证完整清理；不要按 PID 文件盲目杀进程。
- 未配置生产 WSGI/HTTPS/可信代理、多 worker 广播、系统守护服务或开机自启；N3–N8 仍未验收。

## 本批验证

- 新增 18 个本地启动单元回归：权限/链接、配置和部分初始化拒绝、互斥锁、业务环境隔离、运行时读取初始凭据、Cookie 隔离、构建失败短路及共用 MySQL 参数无副作用。
- `make test-startup` 是**单独的 1 个生命周期编排**，使用新建且退出清理的合成实例，绝不使用用户的持久目录或 `WM_TEST_MYSQL_URL`。两个 Chromium 阶段验证真实 CSS/HTTP 登录/词典写入/Socket 订阅，两次启动、一次应用及 MySQL 重启后原 Cookie 和原 UUID 回执仍有效。SQL 独立核对全部应用表结构和行值未变化，实际应用账号不能 CREATE TABLE；检查 SIGTERM、Ctrl+C、重复启动拒绝、重复初始化拒绝及所属 MySQL 退出。它没有纳入常规 Python 或既有 7 个真实浏览器场景的计数。
- 首次编排因测试误取 `words.body.total` 而失败，正确契约是 `words.body.pagination.total`；仅修正测试，保留首次失败日志，未修改业务接口。
- 依赖清单/锁、前端业务源码、`wm_app/` 和八个迁移未改变；数据库为新建的独立本地开发库，没有访问、转换或迁移业务数据。
