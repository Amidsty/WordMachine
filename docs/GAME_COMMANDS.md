# 对局命令：请求幂等与状态版本

本文记录此前完成的事务内请求幂等和状态版本，保留旧对局 JSON 与 `legacy-v1` 评分。此前已完成 [新对局题目快照](GAME_QUESTIONS.md)、[参赛关系及显式转换工具](GAME_PARTICIPANTS.md) 和 [新局答题关系](GAME_ANSWERS.md)，已接入 [结算/评分流水](GAME_SETTLEMENTS.md)；此前提供 [受限旧答案转换工具](ANSWER_CONVERSION.md)，不满足前提的记录、历史评分及其余 JSON 转换仍待审查/实施，授权副本转换尚未完成。

## 数据库与发布

- 显式迁移 `0003_game_requests`：增加 `game.version`（非空 INT、默认 0、非负 CHECK）和 `game_request`。后续已增加快照、参赛、答案、结算及列表索引迁移；完整版本链与当前 `/health/ready` 要求见 [迁移指南](AUTH_MIGRATION.md)。列表索引不改变本协议。
- 已有对局的 0 是启用新协议时的版本基线，不是推算出的历史操作次数；旧 JSON、用户 Rating、评分历史和密码不改写。
- 依赖 MySQL **8.0.16+ / InnoDB** 的 CHECK 和 `FOR SHARE`；迁移入口拒绝较旧 MySQL、MariaDB 和 SQLite。版本下限仅表示功能需求，不是推荐使用已停止维护的补丁版本。
- 新迁移在 DDL 前检查已有同名结构、`game.id` 的 signed INT 主键和 InnoDB。MySQL DDL 仍可能部分提交，失败后需检查/恢复，不能用 `stamp head` 跳过。
- 先备份并在授权副本演练，正式升级时停止旧写入，再交付匹配的后端、迁移和前端构建。旧应用不会推进版本，**不能与新应用混合写库**。
- 不在启动时建表/迁移，不对业务数据库自动执行任何操作。完整升级与回滚边界见 [迁移指南](AUTH_MIGRATION.md)。

## 命令协议

所有现有 HTTP 写接口保留 URL：

- `POST /api/game/create`，业务字段 `dict_id`。
- `POST /api/game/<id>/join|leave|start|cancel|answer|end`；答题仍带 `word_id/answer`。
- Socket 的 `game.join/leave/start/cancel/answer/end` 调用同一套服务，仍需 `game_id/csrf_token`。创建仍只提供 HTTP 接口。

新增元数据：

| 字段 | 规则 |
|---|---|
| `request_id` | 规范带连字符的 UUID v4，可接受大写并规范化为小写；作用域是当前认证用户，不是会话或 Socket 连接 |
| `expected_version` | JSON 整数，范围 0–2147483647，不接受字符串、布尔值、负数或 null；表示客户端所依据的对局版本 |

为兼容旧调用者，这两个字段目前可以省略，但显式 null 为 400。创建不接受 `expected_version`。省略请求 ID 不提供可重放结果，省略预期版本不做乐观并发检查；身份、权限、状态和轮次校验仍然执行。项目内 Vue 大厅和播放页的写操作均已携带请求 ID，已有对局操作也携带版本。

成功命令在原响应基础上增加 `version`；提供请求 ID 时还回传规范化的 `request_id`。大厅摘要、`GET /api/game/<id>` 和 `game.update` 均含 `version`。

### 幂等规则

1. `(actor_id, request_id)` 为联合主键。同一用户、同一 ID、同一有效命令返回**首次成功的原业务结果**，不再次报名、创建、答题、取随机分数或结算。
2. 指纹包括操作名、目标对局、业务参数和预期版本，不包括 Cookie、CSRF 或伪造身份字段。答题沿用原去首尾空白/小写规则后计算指纹。
3. 已成功的 ID 用于不同操作、对局、答案或预期版本，返回 `409 / request_id_conflict`。
4. 原成功结果在状态/轮次/版本检查之前读取，因此正常重复请求不会因对局已经推进而错误失败。身份与 CSRF 校验仍在入口先执行：注销、封禁或失效会话不能通过重放绕过认证。
5. 失败事务不保留请求记录；操作、评分、版本和请求结果一同回滚。提交结果因断线不明时，可以由调用者**手动使用原 ID 和原有效参数**重试。服务端和客户端都不自动重放写请求。
6. 跨 HTTP/Socket、新会话及重建应用实例均从同一数据库记录恢复结果。没有仅存在进程内的去重缓存。

重放返回的是**原回执，不是当前状态**。例如已结束的对局重放首次成功结束请求，仍返回原来的 `already_finished=false` 和原版本；重新发起结束命令才会返回 `already_finished=true`。应重新 GET 状态，或使用 `game.update`，不能把旧回执覆盖到新状态。

### 版本规则

- 创建版本为 0；每个成功且改变对局的命令推进一次版本。
- 最后一题的答题与自动结算是一个命令，只推进一次；已结束对局的无操作重复结束不推进。
- 非重放命令的 `expected_version` 与锁定行不符时返回 `409 / stale_game_version`，不写入任何业务数据或请求记录。刷新状态、重新确认意图后使用新 ID 提交。
- 显式参赛/答案转换工具也在对局锁内校验预期版本，成功切换存储来源时加一；已规范化的重复转换不加。旧成功请求仍重放原回执，不因转换重新执行。
- 版本只排序**对局命令及显式存储转换**。词典文本、用户名以及其他对局引起的个人评分历史变化，不推进本局版本；它不是完整返回对象的 ETag。新对局题面/答案已由创建时快照隔离，旧对局仍引用现有词典；版本不能替代快照或历史恢复。
- Vue 播放/详情页拒绝较低版本的状态，同版本仍允许更新展示资料；回执不累加成绩，迟到的旧答题成功回执不能清除新请求的 pending 状态。

## 事务与锁顺序

`services/game.py` 的统一执行入口管理：

1. 预留请求主键；重复请求等待首次事务完成。
2. 锁定对局行，校验预期版本，再执行原有权限/状态/轮次规则。
3. 需要评分时按用户 ID 固定顺序加排他锁；新参赛关系写入先按同一顺序取得用户共享锁，再修改关系行，避免 FK 以随机出场顺序取锁。两类操作不会在同一命令中从共享锁升级为评分排他锁。
4. 完成业务写入、版本推进和请求结果保存，统一提交；提交之后才广播。

`services/game_requests.py` 只负责元数据校验、请求指纹、原回执读取和保存，不复制业务规则。新对局通过 `game_questions.py` 在同一事务捕获和插入全部题目；成功创建的重放不重新捕获。题目读取适配不改变上述评分锁顺序。`game_participants.py` 只适配参赛存储，不复制权限、随机排序或评分规则；参赛变更同样与回执原子提交。`game_answers.py` 在有序用户锁之后追加答案，轮次主键及快照/参赛者外键不代替服务端校验；答案、数量、最终结算、版本和回执统一提交。新局不双写 `result` JSON，原答题协议与实际随机评分保持不变。`game_settlements.py` 统一保存今后的结算（包括尚未结束旧局），不再双写评分 JSON；对用户最新流水指针按主键做当前读，避免早于等待用户锁的旧快照及空范围 gap lock。结算头、评分行、余额/指针、最终答案和回执一起提交，不锁其他对局；不转换或重算已经完成的历史。

两个不能随意改变的锁细节：

- 请求记录的 `actor_id` **有意不设用户外键**。预留记录时的 FK 检查会提前取得用户共享锁，使原本的“对局 → 排序用户”顺序出现倒置或锁升级死锁。操作者来自已验证的会话，历史请求也不随账号归档丢失。`game_id` 在完成业务后关联已有对局，使用 RESTRICT 外键。
- 重复 INSERT 后只做 `FOR SHARE` 当前读，不升级为 `FOR UPDATE`；多个重复请求可能已同时持有唯一键的共享锁。记录提交后只读，不需要争夺排他锁。

请求记录长期保留，目前不自动清理，`purge-auth` 不处理它们。删除记录会缩短重放保证，不能把清空请求表当成无影响的清理。结果可能含用户答案及评分，需按业务数据管理访问、备份与后续归档。

## 前端意图边界

此前的 [Vue 历史详情](GAME_HISTORY_UI.md) 只消费权威 GET 状态。本批的 [Vue 播放页与 Socket](GAME_PLAYING_UI.md) 共用权威读取/推送资源，命令回执不更新成绩或直接跳转；状态接收防回退，离页/会话变化取消等待、清理订阅和轮询。所有页面已迁移，大厅、播放、详情使用 Vue 导航。

- 大厅同一确认弹窗手动重试使用原 ID/版本；关闭后新确认使用新 ID。
- 创建弹窗同一词典的手动重试保留 ID，改变词典重新提交时生成新 ID。
- 播放页冻结答案/题目/版本/UUID；确认丢失后，即使已观察到新版本，手动重试仍保持原意图，可从 Socket 换成 HTTP。新命令需先显式放弃原回执（不等于撤销已提交操作），再根据新状态确认，不能偷偷改原参数/版本。
- 只读订阅可在握手忙时排队；写命令 volatile 且禁用自动重试，不离线缓存。每次发送前选择传输，一旦尝试发送就不自动 HTTP 重发。只用当前发送关联的 ack 校验 ID，不用重复/无归属的 `game.answer_result`/`game.error` 完成新请求。
- 请求 ID 只在当前页面/弹窗内存中保留，不写 localStorage。重新加载页面后需先核对结果，不能声称能自动恢复所有丢失的客户端意图。
- UUID 优先使用浏览器 `crypto.randomUUID()`；局域网 HTTP 等环境未提供该方法时，使用 `crypto.getRandomValues()` 生成 16 字节并设置 UUID v4 的版本/变体位。两种安全随机 API 均不可用时拒绝生成，不降级为 `Math.random()` 或时间戳；人工重试仍保留原 UUID。此兼容处理不加密 HTTP，生产仍应使用 HTTPS。

## 验证边界

幂等批次新增的真实 MySQL 用例覆盖并发相同 ID 的创建/答题、同版本竞争、跨局评分锁顺序、HTTP/Socket 原回执一致、会话撤销后重放拒绝、请求结果写入失败整体回滚、无操作结束和版本耗尽，以及迁移预检/保留全部旧业务字段。现有数据库用例一并运行。

13 项原浏览器回归仍模拟业务 API。新增独立 `make test-browser-mysql` 使用真实 Chromium、Flask/Socket.IO 和私有 MySQL，验证双用户 Socket/HTTP、重连、实际提交后 HTTP 响应丢失与原 ID 重试、自动/提前结算，并直接核对数据库的唯一记录和余额。它与现有真实 MySQL 并发/故障测试相互补充，不代表所有网络故障、多 worker、授权旧数据副本、备份恢复或生产性能验收完成。
